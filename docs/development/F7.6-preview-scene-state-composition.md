# F7.6 Preview Scene State Composition

**Status:** Completed in the original MVP development record.

## Requirement and scope

Compose pure scene pose/state at time from existing path mathematics and state resolver. This stage supplies data without changing the rendered scene or owning a clock.

## Design and implementation

Composed result includes dimensions/optional background/ordered IDs/assets/x/y/rotation/four states. Interval t=(time−from.time)/(to.time−from.time). Exact nonfinal point uses exact position/outgoing tangent 0; final/after uses incoming tangent 1; single point rotation 0. Explicit unresolved reasons identify affected owner/track, without partial scene or unrelated fallback. Validate minimal movement order/topology and finite outputs; no 60-second core clamp or media/registry side effects.

## Acceptance criteria

1. **AC1:** Pure valid composition returns size/background/ordered states.
2. **AC2:** Retain each owner/asset and independent data.
3. **AC3:** Between points call shared Bézier position using linear time progress.
4. **AC4:** Direction calls shared rotation, no copied math.
5. **AC5:** Exact point pose uses confirmed outgoing/incoming policy.
6. **AC6:** Single point holds rotation 0; after-final holds end pose.
7. **AC7:** Four values use shared discrete resolver.
8. **AC8:** Horn true is data-only without audio.
9. **AC9:** Empty scene composes safely.
10. **AC10:** Invalid time/topology/math/state gives explicit unresolved reason/owner without partial state.
11. **AC11:** Finite time beyond 60 uses actual final-hold semantics, not viewport clamp.
12. **AC12:** Repeat composition preserves all data/state references and JSON.
13. **AC13:** Multiple vehicles give stable independent ordered results.
14. **AC14:** No scene integration, clock, lights or asset resolution yet.
15. **AC15:** Focused tests and the full suite pass.
