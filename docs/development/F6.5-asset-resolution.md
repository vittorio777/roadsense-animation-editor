# F6.5 — Asset Resolution

**Status:** Completed in the original MVP development record.

## Requirement and scope

Resolve validated project references into a runtime asset bundle without duplicating registry rules or embedding metadata in the saved project.

## Design and implementation

Shared single-reference resolution distinguishes missing/type-mismatch with path, assetId, expectedType, reason, message. Validator reuses it while retaining existing errors/order. Bundle resolves optional background and ordered objectId/asset entries, preserving multiple objects using one asset. Any failure returns aggregated errors without partial assets. No preloading/remote checks/dynamic registry/fallback repair.

## Acceptance criteria

1. **AC1:** Valid background resolves actual registered definition/type.
2. **AC2:** No background stays omitted while vehicles resolve.
3. **AC3:** Every vehicle has ordered independent objectId/asset mapping.
4. **AC4:** Shared asset references do not merge/reorder instances.
5. **AC5:** Missing reference has explicit structured classification/location.
6. **AC6:** Wrong registered type is rejected as type-mismatch.
7. **AC7:** Aggregate all errors in background-then-object order.
8. **AC8:** Unresolved result exposes no partial assets member.
9. **AC9:** Metadata matches registry without a second source.
10. **AC10:** Validator public result/text/order remain compatible.
11. **AC11:** Frozen/success/failure leaves model/IDs/order/store untouched.
12. **AC12:** No replacement/reset/load/error presentation yet.
13. **AC13:** Focused tests and the full suite pass without dependency or design changes.
