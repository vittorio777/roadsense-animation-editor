# F4.7 — Point Position Mutation

**Status:** Completed in the original MVP development record.

## Requirement and scope

Move an existing point and update connected resolved endpoints without rebuilding paths or translating controls. Scene drag and properties must share the operation.

## Design and implementation

Finite-only updateMovementPointPosition replaces target point/ancestor containers while retaining all path arrays/objects/controls and untouched point references. A middle point supplies incoming P3 and outgoing P0; first/last supply one endpoint. Renderer, guides and position/tangent/rotation resolve updated IDs. UI handles bounds; store accepts arbitrary finite logical coordinates.

## Acceptance criteria

1. **AC1:** Update target coordinates only, retaining ID/time.
2. **AC2:** Resolve changed endpoints by point ID without copied coordinates.
3. **AC3:** Middle motion updates incoming end and outgoing start.
4. **AC4:** First/last motion affects one adjacent endpoint.
5. **AC5:** Retain paths array, objects, IDs, endpoint IDs/count/order.
6. **AC6:** Keep default/edited control references and absolute coordinates.
7. **AC7:** Shared mathematical outputs update affected paths and preserve unrelated results.
8. **AC8:** Scene curves/guide endpoints move; handles remain fixed.
9. **AC9:** Preserve selection and current time.
10. **AC10:** Preserve other points/vehicles, background and state references.
11. **AC11:** Invalid/misowned/non-finite/repeated requests are complete no-ops.
12. **AC12:** Scene/property entries use one semantic mutation.
13. **AC13:** No topology operations, preview, automatic rotation or new UI.
14. **AC14:** Endpoint/reference/core/render/selection/invalid/regression checks pass.
