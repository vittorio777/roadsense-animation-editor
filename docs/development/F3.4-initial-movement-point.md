# F3.4 — Initial Movement Point

**Status:** Completed in the original MVP development record.

## Requirement and scope

Verify every new vehicle immediately has one zero-time point at its logical spawn position, regardless of playhead time. This extends validation of existing creation rather than adding point UI.

## Design and implementation

Retain the shared vehicle factory. Initial movement is points:[{id, time:0, x, y}], paths:[]. The validator checks point objects, non-empty identity, finite nonnegative times and finite coordinates, and requires a zero-time point without silently repairing input.

## Acceptance criteria

1. **AC1:** New vehicle has exactly one initial point and no paths.
2. **AC2:** Its time is strictly zero.
3. **AC3:** Coordinates exactly match logical spawn position.
4. **AC4:** Vehicle, point and initial state IDs are non-empty and unique.
5. **AC5:** Adding at currentTime 3.3 preserves that editor time but creates a zero-time point.
6. **AC6:** Seeking/snapping preserves project reference and point count/identity/time/position.
7. **AC7:** Validator accepts factory-created movement.
8. **AC8:** Reject empty points or missing zero-time point with a clear error.
9. **AC9:** Reject malformed IDs, negative/non-finite time and non-finite coordinates without repair.
10. **AC10:** No marker, point selection, second point or path.
11. **AC11:** Existing scene, properties, dragging, ruler, playhead and snapping remain stable.
12. **AC12:** Factory, store, timeline integrity, acceptance/rejection and regression checks pass.

## Verification and acceptance

- Original run: 18 files / 85 tests, strict checking and build passed.
- Tests confirmed creation at editor time 3.3 still has point time 0 and (800, 450), uniqueness, no seek mutation and validator failures.
- Browser at 1280 × 720 showed preserved 3.30-second readout and center position without new UI.
- Human acceptance:  passed; internal defaults were established by tests rather than inferred from the image.
