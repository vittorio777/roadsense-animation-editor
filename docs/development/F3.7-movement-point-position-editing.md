# F3.7 — Movement Point Position Editing

**Status:** Completed in the original MVP development record.

## Requirement and scope

Edit an explicitly selected point by stable identity through marker drag or properties, preserving its time and count. Vehicle-only editing retains the current-time creation workflow.

## Design and implementation

Validated updateMovementPointPosition changes only x/y and preserves untouched references. Marker drag start selects/time-aligns; drag move gives clamped visual feedback; drag end commits once. Point properties expose ID, read-only time and X/Y drafts with Enter/blur, Escape and invalid recovery. Bounds reuse vehicle geometry.

## Acceptance criteria

1. **AC1:** Valid ID mutation changes only target coordinates, retaining ID/time/array location.
2. **AC2:** Dragging a marker updates that point and no other points.
3. **AC3:** Drag start selects its owner/point and aligns time.
4. **AC4:** Drag feedback and commit keep the full vehicle within logical scene bounds.
5. **AC5:** Point properties show identity, read-only arrival time and actual coordinates.
6. **AC6:** Single-axis properties edits preserve the other coordinate and refresh scene.
7. **AC7:** After ordinary seek away, properties still edits selected ID and preserves new editor time.
8. **AC8:** Object-only editing still creates/updates at current time.
9. **AC9:** Unchanged or invalid/misowned requests preserve all store references without creating points.
10. **AC10:** Keep point ordering/identity, other points, paths, states, metadata, time and selection.
11. **AC11:** Scene/timeline retain selected ID; timeline time position stays unchanged.
12. **AC12:** No time editing, conflict, deletion, path or interpolation capability.
13. **AC13:** Mutation, drag, bounds, current-time independence, synchronization and regression checks pass.
