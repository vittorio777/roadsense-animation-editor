# F4.2 — Path Rendering

**Status:** Completed in the original MVP development record.

## Requirement and scope

Draw stored cubic paths in logical scene coordinates without adding editing or motion calculation.

## Design and implementation

resolveBezierPathPoints shares endpoint resolution. Konva Bézier Line receives P0/P1/P2/P3, with amber #f 59 e 0 b, fixed-screen 4 px stroke and round ends. Layer order is surface/background→paths→vehicle/markers→border. Paths are non-listening and visible independently of selection; unresolved endpoints are skipped without data repair.

## Acceptance criteria

1. **AC1:** Use exact endpoint/control data in cubic order, not a regenerated approximation.
2. **AC2:** Render each valid path once regardless of selection.
3. **AC3:** Empty paths produce no curve without regressions.
4. **AC4:** Apply confirmed style and layer order.
5. **AC5:** Share scene scale while preserving fixed screen stroke and saved coordinates.
6. **AC6:** Do not intercept existing click/drag/clear-selection.
7. **AC7:** Endpoint moves update resolved endpoints while controls remain fixed.
8. **AC8:** Creation/reorder/deletion reactively updates nodes without stale curves.
9. **AC9:** Missing endpoints are skipped without runtime exceptions or data changes.
10. **AC10:** Pure rendering/resizing preserves project, time and selection references.
11. **AC11:** No path selection/hover/controls/properties/interpolation/rotation/playback.
12. **AC12:** Geometry/count/style/layers/scale/interaction/reactive/defensive/regression checks pass.
