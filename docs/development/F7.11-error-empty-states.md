# F7.11 Error & Empty States

**Status:** Completed in the original MVP development record.

## Requirement and scope

Provide usable empty/background/unavailable states and playback recovery through existing validation/composition rules.

## Design and implementation

resolvePreviewAvailability is shared by scene/timeline; presentPreviewAvailability maps structured reasons to plain wording and safe vehicle names without raw IDs/enums. Empty scene has one non-blocking guide; a vehicle without background has informational status but stays usable. Unavailable pose/assets shows alert without stale fallback/guessed model, retaining source authoring information. Play disables with reason and stops active clock retaining time; derived status automatically recovers. Load errors stay solely in existing dialog.

## Acceptance criteria

1. **AC1:** No vehicles shows useful guidance without blocking commands/scaling.
2. **AC2:** No background with vehicles is informational; editing/valid preview continue.
3. **AC3:** Combined empty uses one coordinated guide without writing defaults.
4. **AC4:** Every unresolved reason has Preview unavailable wording/name without stale pose/raw internals.
5. **AC5:** Missing/wrong model gives explicit error without replacement geometry or mutation.
6. **AC6:** Empty/unresolved/asset error disables Play with reason; valid recovery enables it.
7. **AC7:** Availability loss stops active playback retaining current time/model.
8. **AC8:** Adding/background selection/fix automatically refreshes derived status.
9. **AC9:** Invalid Load retains existing dialog and valid state without competing error UI.
10. **AC10:** Non-listening overlays preserve recovery editing access.
11. **AC11:** Presentation does not persist errors or alter data/time/selection.
12. **AC12:** Desktop/fallback status/alert semantics and text remain readable without overlap.
13. **AC13:** No repair/partial-load/fallback/onboarding/demo/scale/new model scope.
14. **AC14:** Focused/regression/full checks pass.
