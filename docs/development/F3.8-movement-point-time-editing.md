# F3.8 — Movement Point Time Editing

**Status:** Completed in the original MVP development record.

## Requirement and scope

Edit non-initial arrival times by horizontal timeline drag or properties while preserving identity/position and ordering. Duplicate requests are defensively rejected; visible conflict feedback belongs to F3.9.

## Design and implementation

Store mutation validates ownership, non-finite/negative/occupied times and zero-point protection, re-sorts successful changes and aligns current time when selected. Store data has no 10-second maximum. UI clamps to its current 0–10 range and snaps to 0.1. Nonzero markers drag with temporary preview; zero remains selectable/read-only. Properties supports Enter/blur, Escape and rejected-value restoration.

## Acceptance criteria

1. **AC1:** Update only target time by valid ID, preserving ID/x/y.
2. **AC2:** Re-sort points chronologically without changing identities/positions.
3. **AC3:** Horizontal drag commits clamped/snapped pointer time.
4. **AC4:** Drag selects the target; successful edit retains its ID and moves playhead/time.
5. **AC5:** Properties Enter/blur refresh time, marker, playhead and readout.
6. **AC6:** Both UI entries clamp to 0–10 and snap to 0.1.
7. **AC7:** Zero-time point remains read-only/non-draggable.
8. **AC8:** Duplicate time atomically preserves project/selection/time without conflict UI yet.
9. **AC9:** Invalid/misowned/non-finite/protected/unchanged requests preserve references/count.
10. **AC10:** Other points, vehicle identity, states, empty phase-stage paths and metadata remain intact.
11. **AC11:** Timeline time moves, scene position stays, all views retain the same selected ID.
12. **AC12:** Existing seeking/selection/position/current-time creation behavior remains.
13. **AC13:** No conflict resolution, deletion, topology, interpolation or playback.
14. **AC14:** Mutation/order/drag/input/snapping/protection/synchronization checks pass.

## Verification and acceptance

- Original run: 22 files / 110 tests, strict checking and build passed.
- Browser changed 5.0→snapped 4.2 through properties, then dragged to 6.3; identity and position stayed while all time views followed.
- Zero protection and rejection of occupied 0 were checked; no console warnings/errors.
