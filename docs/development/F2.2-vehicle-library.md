# F2.2 — Vehicle Library

**Status:** Completed; human acceptance passed after visual revision.

## Requirement and scope

Display registered vehicles in a read-only Vehicles section. At this stage browsing did not create instances or change animation/editor state; adding was reserved for F2.3.

## Acceptance criteria

1. **AC1:** List only vehicle-type assets with actual thumbnails and names.
2. **AC2:** Backgrounds and Vehicles are clearly separated.
3. **AC3:** IDs, image sources and names come from the registry, without duplicated definitions.
4. **AC4:** Rendering/browsing preserves project, objects, time and selection.
5. **AC5:** Existing background selection and rendering remain functional.
6. **AC6:** Content fits the 224 px library width, using vertical scrolling when needed and no horizontal overflow.
7. **AC7:** Semantic headings and names identify the vehicles; the read-only library has no Add controls.
8. **AC8:** No vehicle instance, selection, dragging or properties editing is introduced.
9. **AC9:** Filtering/rendering/regression tests, strict checking and build pass.

## Implementation and verification

The library reads vehicle assets directly and renders semantic list items without buttons, drag handlers or store actions. Review feedback prompted redrawing the original car-blue.svg using the existing vehicle reference: rounded body, rear-positioned light roof, dark front trim, right-end lamps and four rectangular wheels.

The original run passed 8 files / 31 tests, strict checking and build. Registry filtering, read-only state protection and background regressions passed. At 1280 × 720 the revised thumbnail and direction were recognizable, text remained inside the panel and console warnings/errors were absent. Dependencies and design documents were unchanged; the 554.60 kB build advisory remained.

The user accepted the revised asset, categories, read-only boundary and layout. The historical car-blue asset was replaced by the two final models later in the MVP.
