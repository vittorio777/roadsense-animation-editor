# F4.5 — Path Position Calculation

**Status:** Completed in the original MVP development record.

## Requirement and scope

Provide a typed pure cubic-position function from the same geometry used by rendering. Time-to-progress mapping, cross-segment resolution and UI motion remain outside this mathematical feature.

## Design and implementation

calculatePathPosition returns Point|undefined and uses B(t)=(1−t)³P0+3(1−t)²tP1+3(1−t)t²P2+t³P3 independently for x/y. Resolve endpoints/controls through one geometry helper. Accept only finite t in[0, 1]; reject missing endpoints without clamping/extrapolation. Preserve precision and all inputs.

## Acceptance criteria

1. **AC1:** Export typed pure API independent of UI/store/browser libraries.
2. **AC2:** Use standard polynomial without rounding/snapping/easing/arc-length adjustment.
3. **AC3:** t=0 equals referenced start.
4. **AC4:** t=1 equals referenced end.
5. **AC5:** Noncollinear samples 0.25 / 0.5 / 0.75 match independently calculated expectations.
6. **AC6:** Equally spaced collinear geometry follows linear progress.
7. **AC7:** Edited controls are authoritative and can change the sampled result.
8. **AC8:** Renderer/calculation share identical four-point order/source.
9. **AC9:** Out-of-range/NaN/infinite t returns undefined, not extrapolation.
10. **AC10:** Missing endpoint returns undefined without input mutation.
11. **AC11:** Repeated calls are deterministic and retain values/references.
12. **AC12:** No tangent/rotation/time resolution/motion/preview/store expansion.
13. **AC13:** Endpoint/sample/linear/edited/shared/invalid/deterministic/isolation checks pass.
