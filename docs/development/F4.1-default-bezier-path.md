# F4.1 — Default Bézier Path

**Status:** Completed in the original MVP development record.

## Requirement and scope

Create default cubic paths between adjacent chronologically ordered points. Rendering, selection, controls and mathematical sampling are separate tasks. A user-approved scope adjustment included minimum topology synchronization after reordering/deletion to prevent invalid intermediate data.

## Design and implementation

Resolve endpoints by IDs; controls lie at one-third/two-thirds of the endpoint line, including coincident endpoints. Synchronization retains existing directed-adjacent objects and controls, removes obsolete connections and creates uniquely identified defaults only for missing pairs. Same-time coordinate edits do not recreate paths.

## Acceptance criteria

1. **AC1:** Save cubic type, endpoint IDs and controls without duplicate endpoint coordinates.
2. **AC2:** Default geometry is finite at thirds for horizontal/vertical/diagonal/coincident endpoints.
3. **AC3:** Non-empty unique IDs support deterministic injected factories.
4. **AC4:** One path per directed adjacent pair; one point gives no paths.
5. **AC5:** Creating the second point creates its first segment.
6. **AC6:** Later creation preserves still-adjacent path references/IDs/controls.
7. **AC7:** Same-time position editing adds no path and preserves its IDs/controls.
8. **AC8:** Seek, selection and unchanged position do not churn references.
9. **AC9:** Reordering/deletion removes invalid links, retains valid ones and creates new adjacency defaults.
10. **AC10:** Preserve states, metadata, vehicle/point identity and editor-state semantics.
11. **AC11:** No rendered path, controls, interpolation or rotation appears yet.
12. **AC12:** A phase 3 point chain with empty paths gets complete defaults upon a successful new-point edit, not unsolicited migration.
13. **AC13:** Geometry/identity/topology/preservation/store/isolation/regression checks pass.
