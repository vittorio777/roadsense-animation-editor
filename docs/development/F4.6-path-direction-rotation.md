# F4.6 — Path Direction & Rotation

**Status:** Completed in the original MVP development record.

## Requirement and scope

Calculate the cubic derivative and signed screen-coordinate direction through pure shared functions. This feature does not rotate scene vehicles or add a time resolver.

## Design and implementation

Tangent B′(t)=3(1−t)²(P1−P0)+6(1−t)t(P2−P1)+3 t²(P3−P2) remains unnormalized. Rotation=atan 2(y, x)×180/π: right 0, down 90, up−90, left 180. The original asset faced+X. Zero tangent remains zero while rotation is undefined; no epsilon/history/higher-derivative guess. Share geometry/domain validation; normalize negative-zero angle to 0.

## Acceptance criteria

1. **AC1:** Export typed pure tangent/rotation APIs without UI/store/browser dependence.
2. **AC2:** Apply exact derivative without normalization/rounding/smoothing/fallback.
3. **AC3:** Endpoints yield 3(P1−P0) and 3(P3−P2).
4. **AC4:** Independent intermediate derivatives match within tolerance.
5. **AC5:** Cardinal angles follow screen-coordinate convention.
6. **AC6:** Arbitrary signed angles match atan 2.
7. **AC7:** Same direction at different magnitude yields same rotation.
8. **AC8:** Edited controls affect current direction.
9. **AC9:** Render/position/tangent/rotation share the same four-point geometry.
10. **AC10:** Invalid t or missing endpoints yields undefined.
11. **AC11:** Zero derivative gives zero tangent and undefined rotation, not fabricated 0°.
12. **AC12:** Deterministic results preserve data/state.
13. **AC13:** No scene rotation/time resolver/rotation track/smoothing UI.
14. **AC14:** Derivative/angles/magnitude/edited/invalid/degenerate/isolation/regressions pass.
