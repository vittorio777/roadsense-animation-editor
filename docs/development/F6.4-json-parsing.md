# F6.4 — JSON Parsing

**Status:** Completed in the original MVP development record.

## Requirement and scope

Read selected file text and parse syntax into unknown, keeping syntax separate from project validity and returning stable failures.

## Design and implementation

parseAnimationProjectJson is the only syntax entry. parsed/value, invalid-json/message and read-failed/message distinguish results. The minimal text():Promise<string> reader calls once and catches sync/rejected reads. Native semantics preserve values/order without defaulting; filenames/MIME/extensions do not establish validity. No store/browser picker UI changes.

## Acceptance criteria

1. **AC1:** Serializer JSON parses to equal project data.
2. **AC2:** Retain native nested/string/Unicode/escape/number/Boolean/null/array semantics.
3. **AC3:** Primitive/array/schema-invalid roots remain parsed unknown, not claimed-valid projects.
4. **AC4:** Malformed/truncated/trailing-comma/empty/whitespace input gives stable invalid-json with no partial data.
5. **AC5:** Do not expose engine-specific SyntaxError wording.
6. **AC6:** Selected-file text is read once and passed to shared parser.
7. **AC7:** Sync throw/rejection gives read-failed without parsing or propagation.
8. **AC8:** Success/failure leaves inputs/project/time/selection/store untouched.
9. **AC9:** Repeat calls give same classification/data without retained state.
10. **AC10:** No asset/replacement/reset/load/error UI; validation remains explicit downstream.
11. **AC11:** Validator/serializer/save regressions retain behavior.
12. **AC12:** Focused tests and the full suite pass without dependency or design changes.
