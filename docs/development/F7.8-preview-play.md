# F7.8 Preview Play

**Status:** Completed in the original MVP development record.

## Requirement and scope

Play from current time through one elapsed-time clock, updating existing scene composition and timeline until the 60-second end. User pause is introduced next.

## Design and implementation

Shared editor range constants and pure advancePreviewTime preserve unsnapped elapsed seconds. Temporary store playback actions are idempotent, restart at 0 when at end and stop on replacement/reset/end. One root requestAnimationFrame clock uses adjacent timestamps and cancels frames on cleanup. Separate cancellation from real-unmount state cleanup so Strict Mode replay does not immediately stop play. Active button was disabled Playing at this stage.

## Acceptance criteria

1. **AC1:** Play starts one frame loop.
2. **AC2:** Continue current intermediate time without snapping/reset.
3. **AC3:** At 60 restart from 0.
4. **AC4:** Advance by actual timestamp delta, not fixed per-frame increment.
5. **AC5:** Preserve continuous non-grid values.
6. **AC6:** Existing composer/playhead/readout/reveal consume shared time without duplicate math.
7. **AC7:** Clamp exactly 60, stop and schedule no further frame.
8. **AC8:** Repeated start/rerender neither doubles loops nor resets.
9. **AC9:** Project/serialized data/geometry/tracks/selection remain unchanged.
10. **AC10:** Unmount/replacement cancels frames; Load retains time 0 reset.
11. **AC11:** Named keyboard Play fits stable desktop/fallback header.
12. **AC12:** No user Pause/Restart/Loop/speed/lights/audio scope yet.
13. **AC13:** Focused tests and the full suite pass.
