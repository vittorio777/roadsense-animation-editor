# F1.1 — Editor Layout

**Status:** Completed. Human acceptance: 2026-09-27.

## Requirement and scope

Build the initial workspace with a toolbar, object library, scene, properties and timeline. App loads Editor; each region has its own component, and Editor composes the top toolbar, middle three columns and bottom timeline. This feature establishes containers and honest static empty states.

Logical scene dimensions belong to F1.2, scaling to F1.3 and desktop layout refinement to F1.4. No animation editing, data changes or dependencies were added.

## Acceptance criteria

1. **AC1 — Entry:** Opening the application displays Editor instead of the foundation placeholder.
2. **AC2 — Regions:** Exactly one of each of the five main regions is present.
3. **AC3 — Placement:** Toolbar is above the library/scene/properties columns; timeline is below.
4. **AC4 — Responsibilities:** Separate components own the regions; Editor only composes layout and has no animation calculations.
5. **AC5 — Empty states:** Regions show headings and static guidance without apparently usable but inactive editing controls.
6. **AC6 — Stability:** Structure tests, existing tests, strict type checking and build pass without dependency changes.

## Implementation and verification

App now loads Editor. Five components and layout tests check unique regions, the entry point and empty states. Project documents and the foundation data model were unchanged.

The original run passed 4 test files / 9 tests, type checking and the production build. The local development page loaded all regions. Browser review confirmed placement, boundaries and empty states; the user accepted the result.
