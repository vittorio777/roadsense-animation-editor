# F4.9 — Point Time Reordering

**Status:** Completed in the original MVP development record.

## Requirement and scope

Preserve all path geometry when a time edit retains order; otherwise synchronize the new directed adjacency without reusing reversed paths.

## Design and implementation

Synchronization returns the original array when every directed pair still matches. Cross-neighbor moves retain valid objects/controls, remove obsolete ones and generate defaults for new pairs. Reversed B→C cannot supply C→B. Selected point follows its new time; retained path keeps selection, removed path falls back to owner. Existing typed rejection/snapping/conflict/protection remain.

## Acceptance criteria

1. **AC1:** Retain point ID/x/y and sort successful time edits strictly.
2. **AC2:** Order-preserving edit retains complete path array/objects/controls.
3. **AC3:** Reordered chain has exactly n−1 valid ordered directed links.
4. **AC4:** Preserve unaffected edited path references and geometry.
5. **AC5:** Remove obsolete paths/IDs/controls without reuse.
6. **AC6:** New pairs receive unique cubic defaults at thirds.
7. **AC7:** Reversed adjacency receives a new ID/default.
8. **AC8:** Removed selected path clears subordinate selection, retaining owner.
9. **AC9:** Still-valid selected path retains controls/highlight.
10. **AC10:** Selected point retains ID; timeline/properties/time follow while scene position stays.
11. **AC11:** Protected/duplicate/negative/non-finite/unknown/unchanged requests return existing typed no-op outcomes.
12. **AC12:** Scene/core consume only new topology with finite results.
13. **AC13:** Preserve unrelated data/references except required time/selection changes.
14. **AC14:** No curve-reversal preservation, new timing UI, deletion or preview scope.
15. **AC15:** Order-preserving/reorder/reversed/default/reference/selection/invalid/core/render regressions pass.
