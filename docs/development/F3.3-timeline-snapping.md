# F3.3 — Timeline Snapping

**Status:** Completed in the original MVP development record.

## Requirement and scope

Snap timeline clicks to the nearest 0.1 second while preserving arbitrary valid precision in animation data and direct store time updates. No snapping controls or playback were added.

## Design and implementation

Apply a timeline-only helper after linear click mapping: round((time-start)/interval), then restore the time, clean floating-point tails and clamp. Midpoints choose the later tick, with magnitude-sensitive tolerance. Both ruler and track use this path; setCurrentTime remains unchanged.

## Acceptance criteria

1. **AC1:** Timeline clicks align to the 0.1-second grid.
2. **AC2:** 3.24 seconds snaps to 3.2.
3. **AC3:** 3.26 snaps to 3.3.
4. **AC4:** Exact midpoint 3.25 snaps deterministically to 3.3.
5. **AC5:** Store stable decimal values such as exactly 3.3; readout shows 3.30 s.
6. **AC6:** Start/end snapping remains bounded: 0.04→0, 9.95→10.
7. **AC7:** Same horizontal ruler/track position yields the same time.
8. **AC8:** Direct setCurrentTime(3.25) retains 3.25 rather than snapping.
9. **AC9:** Only time changes; project, points and selection remain unchanged.
10. **AC10:** Playhead/readout agree with the snapped tick without layout changes.
11. **AC11:** No configuration, movement markers, interpolation, playback or playhead drag.
12. **AC12:** Nearest/midpoint/decimal/endpoint/integration/isolation tests and complete checks pass.

## Verification and acceptance

- Original run: 17 files / 74 tests, strict checking and build passed.
- Deterministic boundary cases and direct-store precision passed.
- Browser clicks showed 3.20 / 3.30 seconds and aligned ticks without layout jumps.
- Human acceptance:  passed; the existing bundle advisory remained.
