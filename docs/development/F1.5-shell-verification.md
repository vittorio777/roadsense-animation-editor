# F1.5 — Shell Verification

**Status:** Completed; user accepted the Phase 1 gate.

## Requirement and boundary

Verify F1.1–F1.4 together before starting scene/vehicle work. This was an integration and documentation feature, with no product or dependency changes.

## Acceptance criteria

1. **AC1:** Prior feature records are complete and their accepted boundaries remain intact.
2. **AC2:** Full tests, strict type checking and build pass; dependencies remain unchanged.
3. **AC3:** Chrome passes 1280 × 720, 1440 × 900 and 1920 × 1080 with visible regions, no overlap/overflow and centered 16:9 scene.
4. **AC4:** Edge passes the same desktop matrix.
5. **AC5:** Resizing preserves 1600 × 900 logical dimensions, uniform scale and animation data.
6. **AC6:** Layout/scale update without reload; below-minimum size preserves a scrollable workspace.
7. **AC7:** No application exceptions, React errors or failed resources appear.
8. **AC8:** Only shell capabilities are present; later features remain outside this gate.
9. **AC9:** The phase report records environment, matrix, results, advisories and captures.
10. **AC10:** After human acceptance, create the feature commit and annotated phase tag on that commit, without an empty phase commit.

## Recorded execution

The original run passed 6 files / 24 tests, strict checking and build. Chrome 153.0.8010.48 and Edge 154.0.4258.37 each passed all three desktop sizes with process exit code 0. Edge also passed the 1024 × 600 fallback.

Seven captures matched their target viewports and showed complete, proportional layouts. No application runtime/resource errors were found. Chrome reported local usage-statistics and external-extension-cache notices; Edge had no error log. These notices were recorded as environment issues.

Dependencies and the five stable project documents were unchanged. The user accepted the browser matrix and fallback. See [Phase 1 report](../testing/phase-1-editor-shell.md) for the captures and consolidated measurements.
