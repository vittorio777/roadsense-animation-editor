# F5.7 — Vehicle State Timeline Hierarchy

**Status:** Completed in the original MVP development record.

## Requirement and scope

Organize timeline data into collapsible vehicle groups and read-only projected state intervals. Adding multiple vehicles and editing intervals remain separate MVP tasks.

## Design and implementation

Render groups from scene.objects in order. Registry name/thumbnail identifies owner with safe unknown-asset fallback. Movement plus five state lanes share time space. Boolean true spans and indicator left/right projections derive from keyframes; open states clip visually only. Collapse is component-local, with internal vertical scrolling. Fix an arbitrary Tailwind grid-class failure using explicit gridTemplateColumns.

## Acceptance criteria

1. **AC1:** An empty timeline retains the ruler, playhead, time readout and guidance, with no vehicle groups.
2. **AC2:** One group per vehicle in data order without changing current add limit.
3. **AC3:** Header uses asset identity; unknown reference has safe fallback.
4. **AC4:** Expanded lane order is Movement, left, right, brake, headlight, horn.
5. **AC5:** Disclosure hides/restores children and aria-expanded without model/time/selection changes.
6. **AC6:** Existing marker selection/drag/conflict/zero protection remain.
7. **AC7:** Boolean intervals show true until false, open ending clips without added keyframe.
8. **AC8:** Indicator left/right/hazard/off projects correctly.
9. **AC9:** Intervals are read-only without persistent IDs; blank clicks retain snapped seek.
10. **AC10:** All time-bearing views align at shared endpoints.
11. **AC11:** Render/collapse/seek neither normalizes tracks nor persists fold state.
12. **AC12:** Internal scrolling contains expanded lanes without resizing editor or obscuring panels.
13. **AC13:** Groups, disclosure controls, lanes and markers have accessible names; projected intervals are read-only.
14. **AC14:** Projection/hierarchy/regression/full checks pass without dependency, design or format changes.
