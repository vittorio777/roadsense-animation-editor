# F3.9 — Movement Time Conflict

**Status:** Completed in the original MVP development record.

## Requirement and scope

Explain duplicate arrival times and reject them atomically, allowing immediate correction. No merging, overwrite, suggested-time repair or conflict persistence.

## Design and implementation

Typed outcomes are updated, unchanged, duplicate-time(with occupied time) and invalid. Only updated mutates. Duplicate checks are per vehicle, allowing equal times across vehicles. Properties restores saved input and alerts; timeline restores marker/playhead and alerts. Clear local feedback on renewed editing/cancel/selection or successful correction; validator reports object-indexed duplicate times.

## Acceptance criteria

1. **AC1:** Return explicit typed outcome rather than requiring inference from project comparison.
2. **AC2:** Same-vehicle duplicate requests preserve every store reference, data/order/time/selection.
3. **AC3:** Same time across different vehicles is valid.
4. **AC4:** Properties Enter/blur restores time and displays occupied time.
5. **AC5:** Snapped occupied drop restores marker/playhead and displays the conflict.
6. **AC6:** Text uses role=alert and does not rely on color.
7. **AC7:** Properties input change, Escape, point change or valid commit clears stale error.
8. **AC8:** New drag, ordinary seek or valid drop clears timeline error.
9. **AC9:** Submitting the point's own time is unchanged, not a conflict.
10. **AC10:** Existing current-time position editing updates rather than duplicates a point.
11. **AC11:** Validator rejects same-vehicle duplicate times with location.
12. **AC12:** Validator accepts cross-vehicle equal times.
13. **AC13:** No saved conflict state, merging/overwriting/deleting, path creation or unrelated data change.
14. **AC14:** Typed/atomic/error-lifecycle/validation and regression checks pass.
