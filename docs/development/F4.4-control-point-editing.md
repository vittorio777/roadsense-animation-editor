# F4.4 — Control Point Editing

**Status:** Completed in the original MVP development record.

## Requirement and scope

Drag the selected path's two controls, redraw live and show read-only coordinates. Numeric editing, snapping, linked tangents and playback were outside scope.

## Design and implementation

updatePathControlPoint validates owner, control 1/control 2 key and finite coordinates. Only target control/path and ancestors change. Cyan/magenta fixed-screen handles and non-listening guides join P0→control 1 and P3→control 2. Drag updates stored logical coordinates live, without bounds clamp or rounding, and preserves selection. Controls stay absolute when endpoints move or retained topology changes.

## Acceptance criteria

1. **AC1:** Valid owned control saves finite scene coordinates.
2. **AC2:** Preserve path IDs/endpoints, opposite control, other paths/points/states, metadata, time/selection.
3. **AC3:** Invalid key/references/non-finite/repeated coordinates are full-state no-ops.
4. **AC4:** Only selected path has two handles and two guides.
5. **AC5:** Controls/guides use exact resolved geometry.
6. **AC6:** Distinct colors and stable screen sizing preserve logical geometry.
7. **AC7:** Dragging updates curve/guides live while opposite control and unrelated paths remain unchanged.
8. **AC8:** Drag start/move/end preserves selected path and final data without background bubbling.
9. **AC9:** Properties displays current control coordinates read-only with path metadata.
10. **AC10:** Selection switching/clearing hides old controls immediately.
11. **AC11:** Endpoint motion preserves absolute control coordinates.
12. **AC12:** Retained path keeps controls/selection; removed path hides handles.
13. **AC13:** No numeric control inputs, snapping, linked tangents, motion, deletion or undo.
14. **AC14:** Mutation/render/drag/scale/properties/lifecycle/endpoint/topology/regression checks pass.
