# F3.11 — Movement Verification

**Status:** Completed in the original MVP development record.

## Requirement and scope

Verify the assembled timeline/movement workflow and prior ten feature records before path work. This phase still had empty paths and exact-or-previous-point editing positions.

## Design and implementation

An integration test runs seek, creation, same-time update, selection, coordinate/time edit, duplicate rejection, deletion and final validation. It checks absence of saved editor state and rejection of missing-zero/duplicate projects. Browser verification used in-app Chromium across the desktop and fallback viewports.

## Acceptance criteria

1. **AC1:** Prior ten feature records/commits exist without regressions.
2. **AC2:** Full tests/strict type checking and build pass without dependency or design changes.
3. **AC3:** Seek/snapping synchronizes playhead/readout without changing project or point count.
4. **AC4:** Creation gives one zero-time point with editable position but protected time/deletion.
5. **AC5:** New-time edit creates, same-time edit updates the stable ID in order.
6. **AC6:** Scene/timeline selection aligns properties, selected identity and time.
7. **AC7:** Marker/property coordinates edit the same point without changing time/count.
8. **AC8:** Timeline/property time edits snap/clamp/re-sort and preserve ID/position.
9. **AC9:** Conflict gives accessible feedback and full atomic state preservation.
10. **AC10:** Deletion removes both markers, keeps owner/time and falls back to previous point.
11. **AC11:** Final model preserves zero, unique ordered times, empty paths, states and editor-state separation.
12. **AC12:** Validator accepts legal data and rejects missing-zero/duplicate cases.
13. **AC13:** Three desktop in-app Chromium sizes show usable, unclipped controls and preserved data.
14. **AC14:** 1024 × 600 scrolling retains access; no application exceptions/resource failures.
15. **AC15:** No path/interpolation/rotation/state/persistence/playback/multi-vehicle/deletion-confirmation expansion.
16. **AC16:** Phase report/index captures environment, workflow, matrix, invariants and limitations.
17. **AC17:** Human acceptance:  precedes feature commit and annotated phase tag without extra empty commit.
