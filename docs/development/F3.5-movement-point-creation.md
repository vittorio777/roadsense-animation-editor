# F3.5 — Movement Point Creation

**Status:** Completed in the original MVP development record.

## Requirement and scope

Create a movement point only when position is actually changed at a new time. Seeking alone must not write data. Selection, path generation and interpolation remain separate features.

## Design and implementation

Resolve the exact-time point or the latest earlier point as a read-only editing fallback. Both dragging and properties call one store mutation: update the existing time/ID or create a unique point and sort by time. Equal-position commits are no-ops. Preserve paths, states, metadata, time and object selection.

## Acceptance criteria

1. **AC1:** Seeking from the initial point to 3.3 creates no data/reference change.
2. **AC2:** Dragging to a new position at 3.3 creates a point at that time.
3. **AC3:** Properties editing at a new time creates a point and inherits the other fallback coordinate.
4. **AC4:** Committing the displayed fallback position unchanged creates no point.
5. **AC5:** Zero-time edits update the original point and retain its identity/count.
6. **AC6:** Repeated edits at 3.3 update its existing identity without duplicate time.
7. **AC7:** Creating at 5 then 2 saves points in 0, 2, 5 order.
8. **AC8:** Exact-time scene/properties display the corresponding point coordinates.
9. **AC9:** At a time without a point, display the latest earlier point without mutation.
10. **AC10:** New IDs are non-empty/unique; unrelated animation/editor data remain unchanged.
11. **AC11:** No markers, subordinate point selection, paths or interpolated motion.
12. **AC12:** Creation, resolution, sorting, identity, no-op and isolation/regression checks pass.
