# F7.14 Full MVP Acceptance

**Status:** Completed in the original MVP development record.

## Requirement and scope

From an empty project complete creation→movement/path/state editing→preview→save→reload→load and error recovery. This final release gate uses two models to exercise workflow, while F7.13 supplies scale evidence.

## Design and implementation

tests/mvpAcceptance.test.ts composes real store/path/preview/persistence; pre-save snapshot and second serialization are the oracle. Automated profile uses 4 / 2 points on two owners; actual browser project uses 4 / 3, reaching 30 seconds. Include duplicate rejection, deletion cancel/confirm, model lights and transport. Browser verification used in-app Chromium; independent Chrome/Edge channels were unavailable.

## Acceptance criteria

1. **AC1:** Empty workspace has usable guidance/unavailable Play without invalid data.
2. **AC2:** Create intersection plus final Sedan/Sport with correct identity/defaults/spawn/counts.
3. **AC3:** Cross-panel owner/point/path/state selection and properties agree without data mutation.
4. **AC4:** Movement edits snap/order/reject duplicates atomically, protect 0 and delete only confirmed target.
5. **AC5:** One cubic per adjacency shares geometry with preview and no stale topology references.
6. **AC6:** State point/interval edits share keyframes, duration/indicator overlap rules and motion isolation.
7. **AC7:** Mixed vehicles/deletion stay isolated; cancellation non-mutating without orphan/stale selection.
8. **AC8:** All spans/scroll/seek/play/pause/resume/end 60 synchronize and do not author data.
9. **AC9:** Both model geometry/lamps/beams match rotation, without scene branches or horn sound/icon.
10. **AC10:** Real toolbar save→empty→load restores full oracle and reset state; second serialization equivalent.
11. **AC11:** Invalid JSON/data/assets preserves valid project, understandable operable dialog and later retry.
12. **AC12:** Plan desktop Chrome/Edge matrix plus 1024 × 600 fallback; report actual available browser coverage explicitly.
13. **AC13:** Prior records/Phase 1–6 tags and scale gate remain represented without regressions.
14. **AC14:** Human acceptance:  precedes completed records, one feature commit and v 0.1-editor-mvp tag, without unrelated expansion.
15. **AC15:** Focused tests, the full suite, strict type checking, production build and diff checks pass with reviewed pre-existing advisories.
